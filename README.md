# Commerce One · 리뷰 파일럿

합성 주문의 **요청 기록 → 주문 상품 리뷰 작성·저장 → 상품 상세 위젯**을 검증하는 로컬 데모입니다. 리뷰 관리자와 권한 확인으로 표시한 합성 원본 4행의 가져오기를 포함합니다.

카페24 API·OAuth·실제 상점·메시지 발송·스킨 변경·결제에는 연결하지 않았습니다. 화면의 구매 확인은 **합성 테스트 주문 확인**이며 운영 구매 검증이 아닙니다. 모든 데이터는 개발용입니다.

## 실행

Node.js 22.13 이상과 npm이 필요합니다. 검증 환경은 Node 22.23.0입니다.

```sh
npm ci --ignore-scripts
npm run build
npm start
```

브라우저에서 **http://127.0.0.1:4173** 을 엽니다. 수신 주소와 허용 Host가 `127.0.0.1`로 고정되어 있으므로 `localhost` 이름이나 LAN 주소로 접속하지 마세요. `PORT`로 1024~65535 사이의 다른 포트를 지정할 수 있습니다. 종료는 Ctrl+C입니다.

1. 홈의 **관리자 데모 열기**를 누릅니다. 직접 `/admin`으로 갔다면 **합성 관리자 시작**을 누릅니다.
2. `SYN-O-100`의 요청 기록을 생성하고 **테스트 작성 링크 열기**를 누릅니다. 재클릭해도 같은 요청입니다. 발송은 없습니다.
3. 합성 구매자 A를 선택하고 리뷰를 작성합니다. A의 주문에는 머그와 파우치만 있습니다. B는 별도 주문 `SYN-O-200`의 구매자입니다.
4. **상품 상세에서 확인**으로 이동해 상품 연결과 `테스트 주문 확인 · 합성 데이터` 표시를 확인합니다.
5. 관리자로 돌아가 **권한 확인된 합성 표본 가져오기**를 누르면 정상 2행이 저장되고 매핑 실패·중복 불명확 2행이 검토 큐에 남습니다. 재실행 시 추가 저장되지 않습니다.

입력은 합성 문장으로만 시험하세요. 임의 파일이나 실제 고객 리뷰를 가져오는 경로는 제공하지 않습니다.

## 임시 정책과 저장

아래는 mock 검증용 개발자 가정이며 운영 확정 정책이 아닙니다.

| 항목 | 로컬 정책 |
|---|---|
| 대상 주문 | 합성·결제 완료·전체 배송 완료만 허용. 부분 배송·취소·반품·미결제는 주문 전체 보류 |
| 요청 키 | 주문 ID. 요청은 주문당 1개, 재처리 시 같은 기록·링크 반환 |
| 리뷰 키 | 주문 ID + 서로 다른 상품 ID. 같은 상품의 옵션/수량/복수 라인은 이 데모에서 하나로 취급 |
| 제출 | 별점 1~5 정수, 텍스트 3~1,000자. 같은 내용 재제출은 원래 기록 반환, 내용 변경은 409. 수정 없음 |
| 링크 | 요청 ID와 주문·만료시각을 HMAC으로 보호. 생성부터 7일. 매 접근 시 구매자·주문 상태 재확인. 만료 후 재발급 없음 |
| 재사용 | 남은 상품 작성에 사용. 전부 작성하면 신규 작성 종료. 만료 전 동일 제출 재시도만 허용 |
| 세션 | 무작위 HttpOnly/SameSite=Strict 데모 쿠키, 1시간. 누구나 로컬 합성 역할을 선택할 수 있으므로 실제 인증이 아님 |
| 가져오기 키 | 출처 이름 + 원본 리뷰 ID. 내용·상품 불일치는 덮어쓰지 않고 검토 큐로 분리 |
| 공개 응답 | 리뷰 ID·텍스트·별점·합성 표시·출처만 제공. 주문 ID·고객 ID·링크 토큰·원본 전체는 제공하지 않음 |

데이터는 기본 `.local/pilot/state.json`에 보관하며 Git에서 제외합니다. `PILOT_DATA_DIR`로 별도 테스트 디렉터리를 지정할 수 있습니다. 관리자/구매자 세션은 메모리에만 있어 서버 재시작 시 다시 시작해야 합니다.

파일 저장소는 **단일 프로세스 전용**입니다. 디렉터리의 독점 lock, 변경 전 복사본, 전체 유일성 검사, 임시 파일 쓰기·fsync·rename으로 요청과 리뷰를 원자적으로 저장합니다. 디스크 쓰기 실패는 현재 상태에 반영하지 않습니다. 여러 서버·공유/NFS 디스크·전원 장애 내구성을 검증한 데이터베이스가 아닙니다.

강제 종료 후에는 lock을 자동 탈취하지 않습니다. `store.lock`에 적힌 PID가 종료됐는지 먼저 확인한 후 그 잠금 파일만 제거하고 재시작하세요. 실행 중인 프로세스의 잠금을 지우면 안 됩니다. 확정 저장된 데이터와 가져오기 중복 키는 유지됩니다. 합성 데이터를 초기화하려면 서버를 종료한 뒤 해당 테스트 데이터 디렉터리를 별도 보관하거나 제거합니다.

## 검사와 증거

```sh
npm run lint
npm run typecheck
npm test
npm run test:e2e
# 전체 검사
npm run check
```

E2E는 설치된 Google Chrome을 사용합니다. 별도 브라우저 다운로드 없이 `channel: chrome`을 지정했습니다. Chrome이 없으면 설치하거나 `playwright.config.ts`를 승인된 로컬 Chromium 구성에 맞춰 바꾸세요. 데스크톱 1440×1000과 iPhone 13 크기의 모바일 Chrome 에뮬레이션을 검사합니다. 실제 iOS Safari 검증은 아닙니다.

2026-11-06 결과: 린트·TypeScript 검사·빌드 통과, Node 단위/통합 **20/20**, 브라우저 E2E **8/8**. 타입 검사는 서버·테스트·E2E TypeScript를 포함하며, UI JavaScript는 ESLint와 브라우저 흐름으로 검사합니다. 실행 상세·미실행 범위는 [검증 보고서](docs/VERIFICATION.md), 보존한 실행 출력은 [check.log](docs/evidence/check.log)를 보세요.

## 구현 경계

- `src/domain.ts`: 요청·작성 권한·만료·중복·가져오기와 공개 projection.
- `src/store.ts`: 단일 프로세스 파일 트랜잭션 및 유일성 불변식.
- `src/mock.ts`: 고정 합성 주문·상품과 이용 권한 확인 표시가 있는 합성 표본.
- `src/types.ts`의 `Platform`: mock 데이터 경계. 실제 카페24 어댑터는 구현하지 않음.
- `src/server.ts`: 로컬 HTTP, 역할별 세션, Host/Origin·JSON 크기·CSP 경계.
- `public/`: 관리자·작성·상품 미리보기. 위젯은 선택 모듈로 분리하여 구매 시뮬레이션 이벤트와 독립.
- `scripts/network-guard.mjs`: 기본 실행 경로에서 outbound 소켓·HTTP(S)·TLS·HTTP2·fetch·DNS·UDP 차단. 숫자형 루프백 수신 주소 확인만 허용. 브라우저는 CSP로 같은 출처만 허용하고 E2E도 외부 요청을 차단.

네트워크 가드는 우발적 연결 방지 장치이며 악의적인 코드나 사용자에 대한 OS 보안 경계가 아닙니다. `PILOT_MODE`는 mock만 허용하며 실몰 자격증명을 읽거나 사용하는 코드가 없습니다.

실제 연동은 공식 인터페이스·버전·권한, 구매자 인증, 상점 주문 상태 매핑, 후기 데이터 연결, 스킨 삽입과 실제 브라우저 QA가 확인된 후 별도로 진행해야 합니다. 이 데모의 구매 버튼은 문구를 보여주는 시뮬레이션이므로 실제 구매 동선의 비간섭을 입증하지 않습니다.
